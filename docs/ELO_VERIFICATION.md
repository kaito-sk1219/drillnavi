# Elo 適応出題の検証記録

検証日: 2026-08-11 / 検証スクリプト: `experiments/sim_elo.py`

## 検証の目的

`core/elo.py` を実装するにあたり、以下を実データ投入前に確認する。

1. 推定能力 theta が真の能力に収束するか
2. 実現正答率が目標正答率（grow: 0.75）の近傍に保たれるか
3. 項目難易度 beta をコールドスタートから同時推定できるか
4. 旧方式（±1レベル）の難易度暴走が解消されるか

## 実験設定

| 項目 | 値 |
|---|---|
| 仮想生徒 | 1000人、真の能力 theta* ~ N(0, 1.2) |
| 項目バンク | 200件、真の難易度 beta* を [-3, 3] に等間隔配置 |
| 出題数 | 1人あたり120問 |
| 候補プール | 1問ごとに項目バンクから24件を抽出して選択 |
| 正誤の生成 | P = sigmoid(theta* - beta*) のベルヌーイ試行 |

推定側は theta を 0 から開始し、真の値は一切参照しない。

## 結果1: K値のグリッド探索

生徒300人×120問、5シード平均。RMSE は推定 theta と真の theta の二乗平均平方根誤差。

| k_initial | k_decay | RMSE@10問 | RMSE@30問 | RMSE@120問 | 実現正答率 |
|---|---|---|---|---|---|
| 0.60 | 0.10 | 0.742±0.027 | 0.477±0.021 | 0.239±0.012 | 0.758 |
| **0.75** | **0.10** | **0.711±0.029** | **0.451±0.021** | **0.229±0.010** | **0.756** |
| 0.90 | 0.10 | 0.692±0.031 | 0.441±0.018 | 0.234±0.008 | 0.755 |
| 0.90 | 0.15 | 0.698±0.035 | 0.441±0.021 | 0.227±0.012 | 0.757 |

**採用: `k_initial = 0.75`, `k_decay = 0.10`**

上位候補の差はシード間の標準偏差以内に収まっており、この領域では性能がほぼ平坦。
`k_initial = 0.9` はわずかに早期収束が良いが、初回セッションでの推定値の揺れが大きくなる。
初回体験の安定を優先して 0.75 を選んだ。長期の精度差は 0.005 程度で無視できる。

`k_decay = 0` （減衰なし）は120問時点の RMSE が 0.47〜0.71 まで悪化する。
減衰は必須。逆に `k_decay >= 0.25` は収束が早すぎて能力の変化に追随できなくなる。

## 結果2: 収束の推移（項目難易度が既知の場合）

| 解答数 | RMSE |
|---|---|
| 1問 | 1.128 |
| 5問 | 0.893 |
| 10問 | 0.732 |
| 20問 | 0.566 |
| 30問 | 0.485 |
| 60問 | 0.347 |
| 120問 | 0.246 |

実現正答率 **0.755**（目標 0.750）。

**実用上の含意**: 30問（grow モード2〜3セッション相当）で RMSE 0.5 を切る。
初回セッションの出題難易度はまだ粗いので、`initial_theta_for_grade()` で学年から
事前分布を与える措置は有効。

## 結果3: コールドスタート（項目難易度も同時推定）

全項目の beta を 0 から開始した場合:

| 指標 | 値 |
|---|---|
| 最終 RMSE (theta) | 0.717 |
| 実現正答率 | 0.744 |
| 推定 beta と真の beta の相関 | **0.990** |
| beta の平均ドリフト | +0.042 |

**項目難易度の復元は良好**（相関0.990）。実運用でログから難易度を自動較正できる見込み。

ただし theta の精度は既知の場合（0.246）より大きく劣化する（0.717）。
**運用上の対策**: 新規テンプレートの beta は 0 ではなく、学年と問題種別からの
人手の見積もりで初期化すること。ゼロから推定させない。

### 尺度のアンカリングが必要（既知の課題）

theta と beta は差だけが意味を持つため、両方を同時更新すると尺度全体が緩やかに
平行移動する（今回 +0.042）。1回の実験では小さいが、運用が長期化すると累積する。

**Phase 1 での対応**: 較正済みのアンカー項目を数十件固定し、その beta を更新対象から
外す。または定期バッチで beta の平均を 0 に再センタリングする。
**この対応は Web 実装より前に決めること。** 後から尺度を直すと過去の theta が無意味になる。

## 結果4: 旧方式との比較

旧 `_run_grow_session`（1問ごとに直近10問窓で ±1 レベル）:

```
実力90%の生徒:  [2,3,4,5,6,7,8,9,10,10,10,...]  ← 9問で最大レベルに張り付く
実力50%の生徒:  [2,1,1,...,1,2,3]               ← 底に張り付いた後に突然上昇
```

新方式は120問を通じて実現正答率 75.5% を維持し、暴走しない。
原因は「純関数 `adjust_difficulty` を、窓をリセットせずにループ内で呼び続けた」こと。
アルゴリズムではなく呼び出し側の設計の誤り。

## 実装中に発見された不具合（修正済み）

`expected_probability` が極端な入力で `math.exp` のオーバーフローを起こし、
また確率が厳密に 1.0 に飽和していた。テスト `test_bounded` が検出。

対応: 符号で場合分けした数値的に安定な形に変更し、戻り値を `PROBABILITY_EPS` で
開区間 (0, 1) に収めた。`beta` にもクランプを追加。回帰テストを追加済み。

uv run python experiments/sim_elo.py
